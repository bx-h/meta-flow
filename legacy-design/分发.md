========================
十、开源分发与一键安装要求
========================

现在需要把 meta-flow 做成一个容易分发的开源项目，而不仅是当前仓库内的一组工具配置。

目标：
1. 该仓库可以发布到 GitHub。
2. 该仓库可以发布为 npm package。
3. 用户可以通过一条命令安装 meta-flow：
   - npx @your-scope/meta-flow@latest install --scope repo
   - npx @your-scope/meta-flow@latest install --scope user
   - npm i -g @your-scope/meta-flow && meta-flow install --scope repo
4. 安装后，用户可以在 Codex 中使用 meta-flow skill、custom agents、模板和校验脚本。
5. 安装过程必须安全、幂等、可回滚，不允许破坏用户已有配置。

重要设计判断：
- Codex Plugin 是真正的分发单元。
- npm package 只是安装器和管理器。
- 不要让 npm package 在 postinstall 阶段自动修改用户系统。
- 只有用户显式执行 meta-flow install 或 npx ... install 时，才可以写入文件。
- 不要默认联网下载额外脚本。
- 不要收集 telemetry。
- 不要上传用户代码、配置或任务内容。

请把上一版的本地结构调整为“开源项目结构”。

========================

请在 plugin/.codex-plugin/plugin.json 中创建 Codex plugin manifest。

plugin.json 至少包含：

{
  "name": "meta-flow",
  "version": "0.1.0",
  "description": "A workflow for turning vague requests into clarified, reviewed, adjudicated, task-level executed, and verified outcomes.",
  "author": {
    "name": "TBD",
    "url": "https://github.com/your-org/meta-flow"
  },
  "homepage": "https://github.com/your-org/meta-flow",
  "repository": "https://github.com/your-org/meta-flow",
  "license": "MIT",
  "keywords": [
    "codex",
    "agent",
    "workflow",
    "multi-agent",
    "skill",
    "meta-flow"
  ],
  "skills": "./skills/",
  "interface": {
    "displayName": "Meta Flow",
    "shortDescription": "Clarify, review, adjudicate, execute, and verify vague tasks.",
    "longDescription": "Meta Flow converts vague user requests into goal contracts, reviewed proposals, adjudicated plans, concrete tasks, execution reports, verification reports, and direction evaluations.",
    "developerName": "TBD",
    "category": "Productivity",
    "capabilities": ["Read", "Write"],
    "defaultPrompt": [

注意：
- plugin/skills/meta-flow/SKILL.md 是上一版定义的 Skill。
- plugin/scripts 是 meta-flow 的辅助脚本。
- plugin/templates 是任务状态和报告模板。
- plugin/agent-templates 是 custom agent TOML 的源模板。
- Codex Plugin 本身不一定会自动加载 agent-templates；npm installer 必须把这些 TOML 复制到目标位置。

========================
十二、npm CLI 要求
========================

请创建 npm package。

package.json 要求：
- name 使用占位名 "@your-scope/meta-flow"，不要硬编码真实 npm scope。
- version 初始为 "0.1.0"。
- type 使用 "module"。
- bin 暴露命令：
  {
    "meta-flow": "./bin/meta-flow.js"
  }
- files 字段只包含运行需要的文件：
  - bin/
  - src/
  - plugin/
  - marketplace/
  - README.md
  - LICENSE
  - CHANGELOG.md
- scripts 至少包含：
  - test
  - lint 或 lint:js
  - pack:dry-run
  - verify
- engines 建议 Node >= 20。
- 不要添加 postinstall。
- 不要添加 prepare 中的网络行为。
- 依赖越少越好；如必须引入依赖，先说明理由。

bin/meta-flow.js 要求：
- 使用 node shebang：
  #!/usr/bin/env node
- 调用 src/cli/index.js。
- 支持：
  - meta-flow --help
  - meta-flow --version
  - meta-flow install
  - meta-flow uninstall
  - meta-flow doctor
  - meta-flow verify
  - meta-flow print-paths

CLI 命令设计：

1. meta-flow install

参数：
- --scope repo | user
- --target <path>
- --force
- --dry-run
- --yes
- --no-agents
- --no-plugin
- --backup
- --verbose

行为：
- --scope repo：
  - target 默认当前工作目录。
  - 将 plugin 复制到 <target>/plugins/meta-flow。
  - 创建或更新 <target>/.agents/plugins/marketplace.json。
  - 将 agent-templates/*.toml 复制到 <target>/.codex/agents/。
  - 创建或更新 <target>/.codex/config.toml 中的 [agents] 基础配置。
  - 不覆盖用户已有 agent 文件，除非 --force。
  - 如需覆盖，先备份为 .bak.<timestamp>。
- --scope user：
  - 将 plugin 复制到 ~/.codex/plugins/meta-flow。
  - 创建或更新 ~/.agents/plugins/marketplace.json。
  - 将 agent-templates/*.toml 复制到 ~/.codex/agents/。
  - 创建或更新 ~/.codex/config.toml 中的 [agents] 基础配置。
- 所有写操作必须幂等。
- dry-run 只打印将要执行的操作，不实际写入。
- 安装完成后打印下一步：
  - 重启 Codex。
  - 在 Codex 中尝试提到 $meta-flow。
  - 或运行 meta-flow doctor。

2. meta-flow uninstall

参数：
- --scope repo | user
- --target <path>
- --dry-run
- --yes
- --keep-tasks
- --verbose

行为：
- 删除由 meta-flow install 创建的 plugin 目录。
- 从 marketplace.json 中移除 meta-flow entry。
- 删除 meta-flow 安装的 agent TOML。
- 默认不删除用户任务数据 .meta-flow/tasks。
- 如果 --keep-tasks，明确保留任务目录。
- 不删除用户手动修改过且无法确认来源的文件，改为提示。
- 所有删除前必须有 dry-run 或确认，除非 --yes。

3. meta-flow doctor

行为：
检查：
- 当前是否安装了 Codex CLI。
- plugin 是否存在。
- marketplace.json 是否存在且 JSON 合法。
- meta-flow plugin entry 是否存在。
- SKILL.md 是否存在且 frontmatter 合法。
- custom agent TOML 是否存在。
- .codex/config.toml 是否包含合理 agents 配置。
- Python 脚本是否可执行或可通过 python 调用。
- 示例 JSON 是否能通过校验脚本。

输出：
- PASS / WARN / FAIL。
- 对每个 FAIL 给出修复建议。
- 不自动修复，除非用户运行 install --force。

4. meta-flow verify

行为：
- 校验本 package 内 plugin 结构。
- 校验 plugin.json。
- 校验 SKILL.md frontmatter。
- 校验所有 agent TOML 必填字段：
  - name
  - description
  - developer_instructions
- 运行 Python 脚本 --help。
- 运行 sample-task 校验。
- 用临时目录模拟 repo install 和 uninstall。

5. meta-flow print-paths

行为：
打印 repo scope 和 user scope 下会写入的路径，方便用户理解安装范围。

========================
十四、Custom Agents 安装策略
========================

由于 custom agents 的加载位置是：
- 用户级：~/.codex/agents/
- 项目级：.codex/agents/

所以 npm installer 必须把 plugin/agent-templates/*.toml 复制到对应目录。

复制规则：
- 文件名保持一致。
- 文件顶部加注释：
  # Installed by meta-flow.
  # Source: https://github.com/your-org/meta-flow
  # Do not edit unless you know what you are doing.
- 如果目标文件不存在，直接创建。
- 如果目标文件存在且包含 meta-flow install marker，可以覆盖或更新。
- 如果目标文件存在但没有 marker，不覆盖；输出 conflict warning。
- --force 时才覆盖，并先备份。
- uninstall 时只删除带 marker 的文件。

.codex/config.toml 处理：
- 如果不存在，创建：
  [agents]
  max_threads = 6
  max_depth = 1
- 如果存在：
  - 不要重写整个文件。
  - 如果 [agents] 不存在，追加。
  - 如果 max_threads 或 max_depth 已存在，不强行覆盖，只输出建议。
  - --force 时可以更新，但必须备份。

========================
十八、安装器实现细节
========================

请实现跨平台路径逻辑。

路径规则：

repo scope：
- target = 用户传入 --target 或 process.cwd()
- pluginTarget = <target>/plugins/meta-flow
- marketplaceTarget = <target>/.agents/plugins/marketplace.json
- agentsTarget = <target>/.codex/agents
- codexConfigTarget = <target>/.codex/config.toml

user scope：
- home = os.homedir()
- pluginTarget = <home>/.codex/plugins/meta-flow
- marketplaceTarget = <home>/.agents/plugins/marketplace.json
- agentsTarget = <home>/.codex/agents
- codexConfigTarget = <home>/.codex/config.toml

安全函数：
- ensureInside(parent, child)
- copyDirSafe(src, dest)
- writeJsonPretty(path, obj)
- readJsonOrDefault(path, defaultValue)
- backupIfExists(path)
- hasMetaFlowMarker(path)
- mergeMarketplace(existing, entry)
- patchCodexConfig(path, options)

- marketplace: /path/to/repo/.agents/plugins/marketplace.json
